---
name: OpenAPI codegen drift
description: Frontend type errors against generated client types usually mean codegen wasn't re-run.
---

Frontend types like `Expert`, `Booking`, `PlatformStats`, `ExpertInput`, `BookingInput` come from `@workspace/api-client-react` and `@workspace/api-zod`, which are **generated by orval from `lib/api-spec/openapi.yaml`**.

When you add/change a field on a route response or request body, you must:
1. Update `lib/api-spec/openapi.yaml` (the source of truth).
2. Run `pnpm --filter @workspace/api-spec run codegen` (runs orval + `tsc --build` for libs).

**How to apply:** If a frontend file errors with "Property X does not exist on type Foo" and `Foo` is a generated type, check the spec — either the field is missing from the spec, or the spec was updated but codegen wasn't re-run.

**Why:** The server route and the OpenAPI spec are independent. Adding a field to the route's Zod response without updating the spec means the client never learns about it, and frontend code that reads it won't typecheck.
